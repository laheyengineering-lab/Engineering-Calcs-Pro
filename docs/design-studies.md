# Design Studies

`design-studies.html` turns individual calculators into a design-iteration workspace: save several scenarios for one calculator, compare them against a baseline, run a parametric sweep of one input and add the results to the project report. Everything is browser-local (`localStorage`, key `formulaFoundry.designStudies`); there is no backend.

## Supported calculators
| Calculator | Why it was chosen |
| --- | --- |
| Hydraulic/Pneumatic Cylinder Force (`cylinder-force`) | Pure SI function `computeCylinderForce()`, a small set of numeric inputs, clear outputs with units, easily hand-checked. |
| Differential Thermal Expansion (`differential-thermal-expansion`) | Pure SI functions `computeDifferentialExpansion()`; temperature, length and coefficient units; database presets for thermal expansion coefficients; meaningful design-iteration sweeps (e.g. temperature vs movement). |
| Press-Fit Stress (`press-fit`) | Calls the calculator's Lamé model using the selected material database entries and its actual pressure, hoop-stress, force, torque, and optional yield-screening results. |
| Hertzian Contact Stress (`hertzian-contact`) | Supports the existing cylinder/line-contact and sphere/point-contact models separately, including convex, flat, and concave body-2 curvature; body material presets supply E and ν. |
| Shaft Torsion (`shaft-torsion`) | Calls the existing solid or concentric hollow circular-shaft engine; geometry is an explicit scenario selection and a material preset supplies G. |
| Beam Bending Stress (`beam-bending-stress`) | Uses the shared section-property engine and the existing signed extreme-fiber flexure model for all six supported cross-sections and both axes. |
| Beam Deflection (`beam-deflection`) | Uses the shared section-property engine and the existing Euler–Bernoulli closed forms for the four listed support/loading cases; a material preset supplies E. |

### Supported models, inputs, outputs, and sweeps

| Calculator | Scenario inputs and unit groups | Existing outputs exposed | Sweepable continuous inputs |
| --- | --- | --- | --- |
| Hydraulic/Pneumatic Cylinder Force | Bore and rod diameters, working pressure, and optional user-supplied efficiency. Uses length, pressure, force, and area units. | Piston/rod/annular areas; theoretical extension/retraction forces; optional efficiency-adjusted estimates. | Diameters, pressure, and efficiency. |
| Differential Thermal Expansion | Up to three sections per member: length, material or expansion coefficient, and initial/final temperatures. Member A section 1 is required. Uses length, coefficient, temperature, and output-length units. | Per-member free expansion; optional differential movement and final-length difference. | Section lengths, coefficients, and temperatures. Material presets are categorical and cannot be swept. |
| Press-Fit Stress | Interface diameter, diametral interference, hub outside diameter, shaft bore (zero is solid), engagement length, assumed friction coefficient, hub material, and shaft material. Length/interference, stress, force, and torque use the calculator's supported unit choices. | Contact pressure; hub tensile and shaft compressive interface hoop stress; idealized assembly force and torque capacity; hub/shaft/controlling elastic-hoop-stress screening factors only when yield data exists. | Dimensions, interference, length, friction coefficient. Materials are categorical and cannot be swept. |
| Hertzian Contact Stress | Contact model, body-2 shape, body diameters (diameter 2 omitted for flat), cylinder length, force, each body's optional material preset or directly entered Young's modulus and Poisson ratio. Uses the calculator's distance, force, modulus, stress, and contact-size units. | Effective modulus/radius; cylinder line load, half-width and width, or sphere contact radius and centre approach; maximum/mean contact pressure and approximate maximum shear stress/depth. Outputs unique to a model are optional and absent for the other model. | Required dimensions, load, moduli, and Poisson ratios. Contact-model, curvature, and material selections are categorical. |
| Shaft Torsion | Explicit solid/hollow choice, torque, outer diameter, hollow inner diameter, length, and optional material preset or directly entered shear modulus. Uses torque, diameter, length, modulus, stress, angle, and polar-moment units offered by the calculator. | Polar moment, signed maximum shear stress, signed angle of twist, and torsional stiffness. | Torque, diameters, length, and shear modulus. Shaft type and material are categorical. |
| Beam Bending Stress | Cross-section profile, x/y bending axis, that profile's dimensions, and signed bending moment. Uses length, moment, area, inertia, section-modulus, and stress unit groups. | Signed extreme-fiber bending stress; area, centroid, both second moments, and both section moduli. | Moment and dimensions for the selected profile. Profile and axis are categorical. |
| Beam Deflection | One of four loading/support cases, span, applicable point or uniform load, optional material preset or directly entered Young's modulus, cross-section profile/dimensions, and x/y axis. Uses span/section length, force or distributed load, modulus, deflection, moment, area, inertia, section-modulus, and flexural-rigidity units. | Signed maximum deflection and magnitude, location, maximum moment, flexural rigidity, and the same section properties. | Span, applicable load, modulus, and dimensions for the selected profile. Case, profile, axis, and material are categorical. |

Categorical selections are saved as strings alongside the existing numeric-or-blank scenario inputs; schema version 1 and existing numeric saved studies remain compatible. Selecting a material fills its available database properties into the editable numeric fields using the current units; those fields can still be overridden manually, and the saved scenario records both the material and property values. Material selections and other categorical/dependent inputs are not swept. Invalid dependent geometry (for example, concave contact with a smaller body-2 diameter, or a hollow shaft with an oversized bore) produces failed samples/gaps rather than interpolated results.

Cylinder-force is a static pressure-area calculation and does not check rod buckling, seal limits, pressure ratings, or speed. Differential Thermal Expansion reports free expansion only; restraint, contact, or mechanical loading changes movement and may introduce stress not represented by the model. Press-fit calculations use the selected centralized material's E, ν, and optional Sy; there is no custom-material-property or temperature correction in the study model. The press-fit screening factor compares interface hoop stress with yield and is not a code factor of safety. Hertz sphere and cylinder results are distinct models; line and point-contact scenarios cannot be compared directly. Approximate Hertz maximum-shear results retain the calculator's ν ≈ 0.3 coefficients. Beam deflection supports only the calculator's full-span point/uniform loads with pin/roller or fixed-free supports. Neither beam model evaluates shear deformation, buckling, plasticity, fatigue, stress concentrations, dynamic response, or non-ideal supports.

## Expansion to all 18 active calculators
Eleven further calculators were audited and integrated; none were deferred. Each had its calculation extracted into a DOM-free `js/<name>-calculation.js` engine that the calculator page and the adapter both call (page behaviour and numerical results are unchanged; parity tests compare page and adapter output).

| Calculator (`id`) | Engine | Categorical / conditional inputs | Key outputs | Notes and limitations |
| --- | --- | --- | --- | --- |
| Bolt Torque (`bolt-torque`) | `bolt-torque-calculation.js` | none | torque | Simplified T = K·D·F. Nut factor and clamp load are assumed inputs; no prediction of preload or friction distribution. |
| Moment (`moment`) | `moment-calculation.js` | none | signed moment | Force × perpendicular distance with the calculator's sign convention; no other load positions or geometry. |
| Bearing Life (`bearing-life`) | `bearing-life-calculation.js` | bearing type (ball 3 / roller 10/3) | exponent, load ratio, L10 (million rev, rev), L10h (h) | Basic rating life only; not a prediction of actual service life. |
| Column Buckling (`column-buckling`) | `column-buckling-calculation.js` | section (solid/hollow), material, end condition | I, K, effective length, Pcr | Euler elastic buckling only. E comes from the material preset (the page has no editable E). |
| Factor of Safety (`factor-of-safety`) | `factor-of-safety-calculation.js` | mode (stress/load), strength source, material | stress FoS *or* load FoS, strength used | The two definitions use different quantities and are never compared; strength source is part of the comparison key. Material strength is resolved inside the adapter's `calculate`. |
| Fillet Weld (`fillet-weld`) | `fillet-weld-calculation.js` | electrode, load direction (0°/90°), method (LRFD/ASD) | throat, area, F_EXX, nominal and design strength, optional required leg/utilization | Direct load only; LRFD and ASD are not comparable with each other. |
| Helical Spring (`spring-calculations`) | `spring-calculation.js` | material | rate, index, deflection, Wahl factor, shear stress | Round-wire compression spring; no fatigue, buckling or coil-contact checks. |
| Stress & Strain (`stress-strain`) | `stress-strain-calculation.js` | mode (stress/strain/modulus/deformation), material | the mode's own quantity only | Scenarios of different modes are not comparable. |
| Thermal Expansion (`thermal-expansion`) | `thermal-expansion-calculation.js` | condition (free/restrained), material | expansion, final length, strain, optional restrained stress | Restrained stress assumes full restraint and uses E. Temperature is an interval (°C/K/°F). |
| Thick-Walled Cylinder (`thick-walled-cylinder`) | `thick-walled-cylinder-calculation.js` | end condition (open/closed) | radial, hoop, axial stresses, governing hoop | Lamé model; open and closed ends are not comparable and the selection is saved with every scenario and sweep. |
| Thread Strength (`thread-strength`) | `thread-strength-calculation.js` | bolt and internal-thread material | fastener capacity, utilization, optional stripping capacity/utilization, governing capacity | Fastener tension and stripping are distinct modes; no thread-by-thread load distribution. The governing-mode name is text and is not a numeric output; only the lower capacity is reported. |

Scenarios whose models differ (mode, end condition, method, condition, strength source) carry a `comparisonKey`, and the core refuses to compare them even when units match. Categorical inputs are never sweepable.

### Unsupported calculators
None of the 18 active calculators is currently unsupported.

## Architecture
- `js/design-study-core.js` - DOM-free data model, adapter registry, comparison, sweep, persistence/validation and report-snapshot builders (`window.FormulaFoundryStudies`).
- `js/design-study-adapters.js` - one adapter per supported calculator. An adapter declares id/name/revision, unit groups (with conversions delegated to `engineering-units.js`), numeric or categorical input definitions, output definitions (quantity, `plottable`, `comparable`), equations, assumptions, and a `calculate(values, units)` method that **calls the calculator's own calculation engine**. No calculation equations are duplicated in the Design Studies code.
- `js/press-fit-calculation.js`, `js/hertzian-contact-calculation.js`, `js/shaft-torsion-calculation.js`, and `js/beam-study-calculations.js` expose DOM-independent calculation entry points also used by the calculator pages. The beam entry points use `js/beam-section-properties.js`; displayed calculator equations and numerical results remain the same.
- `js/design-study-context.js` - presentation-only engineering context: the panel above the scenarios shows the selected adapter's existing `method`, `equations` (via `equationsFor()` when defined), `assumptions`, `warnings` and `path` link (KaTeX via `FormulaFoundryRenderMath`), plus a conceptual SVG per calculator built with `FormulaFoundryDiagram` (the beam-deflection diagram reuses `FormulaFoundryBeamDeflectionDiagram`). Adapter metadata remains the single source; malformed or missing metadata is skipped. Diagrams use the baseline (or first) scenario's inputs only to set clamped proportions and labels, are labelled illustrative, never calculate or validate results, and need no calculated scenario. A text description and list of drawn values accompany each SVG.
- `js/design-studies.js` + `design-studies.html` + `css/studies.css` - the workspace UI (text is always set via `textContent`).
- `js/study-chart.js` + `css/study-chart.css` - dependency-free SVG line chart shared with the report.

To add a calculator: make sure its script exposes a pure calculation function, add an adapter, register it, and add tests that check results and sweeps against independent hand calculations. Bump the adapter `version` whenever the calculator's results or outputs change; scenarios saved with an older revision are marked stale and cannot be compared until recalculated.

## Data model (schema 1)
`{ schemaVersion: 1, studies: [study] }`, study = `{ id, name, calculatorId, createdAt, updatedAt, baselineId, scenarios[], sweeps[] }`.
Scenario = `{ id, name, calculatorId, calculatorVersion, inputs{id: number|string|null}, units{group: unit}, status: new|calculated|stale|error, error, result, updatedAt }` where `result` is the saved snapshot `{ calculatedAt, calculatorVersion, inputs[{id,label,value,unit}], outputs[{id,label,value,unit,quantity}], equations[], assumptions[], method, warnings[] }`.
Editing an input or unit never changes `result`; it marks the scenario `stale` until the user presses **Recalculate**. Scenarios are never modified by edits to other scenarios (all operations return copies).
Loading validates every study, scenario and sweep; invalid items are dropped individually and reported. Unreadable or other-schema data is not loaded, is never silently overwritten and is copied to `formulaFoundry.designStudies.backup`.

## Comparison
Uses saved snapshots only. Scenarios must be of the same calculator, calculator revision and calculated (not stale/error). Differences are computed against the selected baseline after unit conversion; percentage differences are omitted with an explanation when the baseline is zero or missing, or when the quantity is on an offset scale (temperatures). Differences in optional outputs, units and assumptions are listed. The UI marks changed values but never labels them better or worse.

## Parametric sweeps
One input of a calculated baseline scenario is varied between a start and end value using either a step size or a sample count (2 to **200** samples). Every sample calls the adapter's `calculate()` with all other baseline inputs unchanged. Static input limits (e.g. `> 0`, `<= 100 %`) are checked before the run; sample-dependent failures (e.g. rod diameter ≥ bore) appear as failed rows, as gaps in the chart (marked ×), and are never interpolated. A sweep is a model-based exploration, not a physical test, and values between samples are not calculated.

## Report integration
Scenarios, comparisons and sweeps are added with `FormulaFoundryReport.addSnapshot()`. Entries are frozen copies and may carry optional `study` metadata, `tables[]` (`{caption, columns[], rows[][]}`) and a `chart` (`{type:"line", title, xLabel, yLabel, points[{x, y|null}]}`). The report always prints the numeric tables; the chart is an SVG rendered from the stored points. These are optional extensions to the existing snapshot format; existing entries are unaffected.
